# Future Plans

**Product:** ForgePath (working title) · **Parking lot — nothing here is committed**

> **Related:** [Demand](../product/demand.md) · [Requirements](../product/requirements.md) · [Initial design](../product/initial-design.md) · [BMAD path](../method/bmad-path.md) · [Decision log](../log/decision-log.md)

Where good ideas go so they stop competing with the current step. Each item carries the condition that would make it worth starting. Nothing leaves this file without a [decision-log](../log/decision-log.md) entry.

## Planned — after the solo MVP

Already sequenced in [initial design](../product/initial-design.md) §19 as Phases 2–4: crews with matching, feedback and moderation; weekly review generation; institutional cohort codes and facilitator tools; adaptive difficulty and blocker detection. Each unlocks on the previous phase hitting the requirements §10 thresholds — except institutional tooling, which waits for a signed paid pilot.

## Plausible but unvalidated

| Idea | Unlocks when |
|---|---|
| Portfolio artifacts that outlive the subscription — PDF export, stable URL, employer-readable structured data | Users report the portfolio page is the main value, and try to share it somewhere we don't control |
| Handoff from existing screen-time blockers, so a blocked app surfaces a mission | The idle-moment trigger proves to be how users actually enter the product, rather than a scheduled session |
| Native mobile, for the notification and idle-moment surfaces only | Measured drop-off between notification and first mission that responsive web can't close |
| Facilitated premium cohorts with human review | Facilitator minutes per completed project are measured and bounded — this is the line between a product and an agency |
| Template library beyond the initial six | The existing six show meaningfully different completion rates, so we know what makes a template work |
| Alumni and repeat projects | 25% start another project within 14 days unprompted — the second project is where retention actually lives, and nothing in the current design addresses it |

## Interesting but unjustified

Stated plainly so they aren't mistaken for plans: verified contribution records (needs an employer who says they'd trust it); employer matching (a different business with a different sales motion); peer-to-peer skill exchange (payments, disputes, moderation load out of proportion to the MVP); non-English markets (a distribution decision, not a translation task); an open template ecosystem (only once we know what a good template is).

## Rejected — not "later", but "no"

- **Infinite public feed** — reintroduces the comparison pressure the product exists to counter ([D-008](../log/decision-log.md))
- **Punitive streaks** — produce compliance rather than mastery ([D-004](../log/decision-log.md))
- **Creator monetisation, tokens, cash prizes** — changes why people show up, and not for the better
- **Clinical positioning or diagnosis-gated features** ([D-004](../log/decision-log.md))
- **A single universal confidence score** ([D-009](../log/decision-log.md))
- **AI that produces the user's deliverable** — most tempting to ship, most reliably destroys the product's value ([D-005](../log/decision-log.md))
